# 五维评分量表 · Five-dimension rubric

每维 1-10 分，加权总分 ≤ 50。总分 ≥ 42 为通过线，< 35 建议重写。
Score each dimension 1-10; weighted total out of 50. Pass at ≥ 42; below 35,
go back and rewrite rather than patch.

**量表对两种语言通用**，仅节奏维度的描述口径不同：

| 口径 | 中文稿 | English manuscripts |
|------|--------|---------------------|
| 短句 short sentence | ≤ 15 字 | ≤ 8 words |
| 长句 long sentence | ≥ 60 字 | ≥ 40 words |

这些只是 `scripts/aigc_audit.py` 计数用的口径，**不是目标值**。没有研究给出可沿用的句长
方差 / CV 门槛：在 1% 误报率下句长 CV 只抓到 2.5% 的机器文本（AUROC 0.521），而让模型
"把句长写得更有起伏"反而让检测器更容易认出来（sepia `research/rhythm-syntax.md`）。
These are counting conventions for the audit script, not targets — see the
rhythm dimension below.

**自评分不预测任何检测器的结果。** It is a revision checklist, not a pass
probability: upstream projects that measured their own composite scores found
them near a coin flip at paragraph level (avoid-ai-writing `PROOF.md`).

英文稿的 hedge 加分词：suggests, is consistent with, is associated with,
may indicate, in our sample, we cannot rule out。英文稿的绝对化扣分词：
prove(s), demonstrate(s), establish(es), clearly shows, undoubtedly
（对应 `patterns-en.md` EN10/EN15；中文对应 ZH12/ZH14）。

## 维度 1 · 具体性（Concreteness）—— 权重 1.5×

**定义**：文本中可验证的具体信息密度。

**评分标准**：

| 分数 | 表现 |
|------|------|
| 1-3 | 全文都是抽象概念，几乎没有具体数字、具体作者、具体案例 |
| 4-6 | 有少量具体锚点，但大段落仍然靠"研究表明/相关文献"这类模糊表达推进 |
| 7-8 | 关键论证点都有数据/文献/案例支撑，偶有空话 |
| 9-10 | 每个核心主张都跟可验证锚点；读者可以倒推回原始数据或文献 |

**自测问题**：
- 原稿里**已有**的数字、表号、文献是否都被用来支撑主张，而不是被套话盖住？
- 文献引用是否精确到作者+年份？
- 数据来源是否说明具体数据库、变量、窗口？

**锚点只能来自原稿或作者。** 缺锚点的主张写成 `[作者补：表X第(2)列系数]` 交给作者，
agent 不得自己补数字、补文献、补案例（op7418 / qu-ai-wei / shuorenhua / im-not-ai 一致的硬约束）。

**反面教材**：
> "相关研究表明，数字化转型对企业绩效具有显著影响"

**正面教材**：
> "Acemoglu and Restrepo (2022) 在 QJE 的估计显示，2010-2018 年美国制造业数字化每增加一个标准差，TFP 提升 4.3%（t = 3.81）"

## 维度 2 · 节奏性（Rhythm）—— 权重 1.2×

**定义**：句子长短是否跟着内容走——证据链用长句承载，结论落点可以短；而不是一串长度相近的
中等句子。

**证据的方向**（2026 年新数据修正了旧版的"每 200 字一短一长"配额）：
- 当代模型写得**太少长句**、也**太少极短句**，而不是"方差不够"：im-not-ai 的语料里真正的信号是
  缺长句（`docs/en/evidence.md`），sepia 量到 2025 年模型短句占比 1–4% 对人类 32–33%。
- 机械地交替长短句比不改更糟（lieflat `SKILL.md` 改写原则 3）。修法是**合并**相邻的、说同一件事
  的句子（不加新内容），或把一句里塞的两个判断拆开——不是为节奏造短句、造问句。

**评分标准**：

| 分数 | 表现 |
|------|------|
| 1-3 | 连续 4 句以上长度相近（±15%），证据链被切成碎句，或一段全是中等长度 |
| 4-6 | 偶有长短变化，但长句不承载证据、短句不落在结论上 |
| 7-8 | 证据链用一个长句讲完，关键结论处有自然的短句 |
| 9-10 | 句长跟内容走，与作者本人旧稿的节奏一致（有语料时以作者旧稿为基准） |

**计算方法**（只报告，不设门槛）：

```bash
python3 scripts/aigc_audit.py audit draft.md   # 输出 sentence_length_cv、long_share、similar_length_runs_4plus
```

**自测问题**：
- 有没有连续 4 句以上长度相近的段落？
- 证据链（系数 → 机制 → 对照文献）是被一个长句讲完，还是被切成三四个中等句？
- 有作者旧稿时：改写后的长句占比是否接近作者旧稿？

**不要做**：为了节奏插入"数据讲了另一个故事。"这类口号短句，或"效应在谁身上最强？"后紧接
自问自答——两者都在 stop-slop / avoid-ai-writing 的 AI 痕迹清单上。

## 维度 3 · 谨慎性（Caution）—— 权重 1.3×

**定义**：认识论层面的谨慎表达密度。hedge 词 + 条件限定 + 局限承认。

**评分标准**：

| 分数 | 表现 |
|------|------|
| 1-3 | 充斥"证明了/必然/绝对/充分说明"；不承认局限 |
| 4-6 | 偶有 hedge 表达，但主论证仍然绝对化 |
| 7-8 | hedge 均匀分布，关键结论有条件限定 |
| 9-10 | 主动承认研究局限、样本边界、方法限制，并讨论替代解释 |

**高危词（扣分）**：
- 证明了、充分说明、完全证实、必然导致、绝对、毫无疑问、总是、从不

**加分词**：
- 可能、或许、在一定程度上、在本文样本中、需要审慎解读
- 与...预期一致、为...提供了证据、这暗示可能
- 受限于、由于...局限、无法识别

**自测问题**：
- 每个观察性主张是否恰有一个与设计匹配的 hedge（不是零个，也不是三个叠在一起）？
- 原稿承认的局限是否都还在？原稿**没写**局限时，是否标给作者（`[作者补：局限]`），而不是由 agent 代写？
- 关键系数的表述是否用了条件化语言？

hedge 只按设计强度校准，不按密度配额注入：sepia 的 recreate 规则是"不添加原文和用户都没说的
怀疑或局限"。

---

## 维度 4 · 隐衔接（Implicit Cohesion）—— 权重 1.0×

**定义**：段落之间通过概念自然接力衔接，而非显性关联词。

**评分标准**：

| 分数 | 表现 |
|------|------|
| 1-3 | 段首大量"此外/而且/因此/从而/然而"；段落之间靠连接词硬连 |
| 4-6 | 偶有段首连接词，但过渡基本顺畅 |
| 7-8 | 几乎无段首连接词，段落之间通过概念重叠自然衔接 |
| 9-10 | 过渡完全隐形，读者感觉不到段落切换 |

**检测方法**：扫描每个段落的首句，是否以连接词开头。

**禁用段首词**：此外、而且、并且、然而、因此、所以、从而、于是、进而、另外

**允许的段首**：
- 直接陈述新观点
- 提出下文会用证据回答的真实问题（不为节奏造问句，问完不要立刻自答）
- 呼应上一段的某个概念（如上一段末尾讨论"分析师预测分歧"，下一段开头可以"预测分歧度的下降..."）

---

## 维度 5 · 研究者语气（Researcher Voice）—— 权重 1.0×

**定义**：文本是否呈现了真实研究者的**立场、选择、判断**。

**评分标准**：

| 分数 | 表现 |
|------|------|
| 1-3 | 全文"本文/本研究"作主语，读起来像模板 |
| 4-6 | 有零星研究者选择的痕迹，但仍以第三人称为主 |
| 7-8 | 适度使用"我们"或"本文作者"，展示研究者的方法选择和判断 |
| 9-10 | 清晰呈现研究者的思考路径："我们选择用 X 而不是 Y，因为..."；承认取舍和局限 |

**加分表达**：
- "我们用 [方法] 而不是 [替代方法]，是因为..."
- "这一结果与原本的理论预期相反：……"（仅当作者确认这确实出乎意料）
- "受限于数据，我们无法识别..."
- "我们在稳健性部分尝试了 [N] 种替代设定"（N 取自原稿）

**减分表达**：
- "本文认为..."（过度使用）
- "研究表明..."（不具名）
- "众所周知..."

**自测问题**：
- 人称是否符合目标期刊惯例（CSSCI 多用"本文"，SSCI 多用 "we"）？不为加分硬塞"我们"。
- 是否展示了研究者做过的**选择**（方法选择、样本选择、变量定义选择）？选择理由来自原稿或作者。
- 原稿里的意外发现、预期之外的结果是否被保留下来，而不是被抹平成"符合预期"？

## 总分计算

```
加权总分 = 具体性 × 1.5 + 节奏性 × 1.2 + 谨慎性 × 1.3 + 隐衔接 × 1.0 + 研究者语气 × 1.0
满分 = 10 × (1.5 + 1.2 + 1.3 + 1.0 + 1.0) = 50
```

**评级**：

| 加权总分 | 评级 | 建议 |
|---------|------|------|
| ≥ 42 | A（通过） | 进入 Step 5 冷读复查与 `aigc_audit.py compare` 保真核对；自评分不预测检测器结果 |
| 35-41 | B（待改进） | 聚焦 2-3 个最弱维度再改一轮 |
| 28-34 | C（显著问题） | 返回 Step 3 重写，不要微调 |
| < 28 | D（重写） | 整段段落级重写，或从头来过 |

## 常见误区

1. **不要为了高分造句**：例如硬塞一个"意外发现"，读起来反而假。真实研究者会对**实际**的意外发现做讨论。
   avoid-ai-writing 的"never inject"清单同样适用：不编造研究者视角、不制造利害、不为反差而反差、
   不造口号式短句、不加破折号戏剧化、不编具体细节。
2. **不要用生僻词降困惑度**：如把"重要"改成"攸关"——这会损害学术严肃性。
3. **评分不是唯一目标**：通过率高但论证失真，得不偿失。**学术诚信优先于检测率**。
